# 에이전트용 안내

이 도구에서 에이전트가 하는 일은 둘이다. **① 파일별 한 줄 요약을 채운다. ② 사람이 남긴 질문에 답한다.**

## 언제

PR을 올려 번호가 나온 직후에 요약을 채운다. 사람이 PR을 여는 동안 채워지면 되므로 기다릴 필요가 없다
(확장이 3초마다 다시 읽는다). 데몬이 꺼져 있어도 기록은 된다 — 파일에 직접 쓰기 때문이다.

```bash
npm run check    # 0 = 데몬 떠 있음, 1 = 꺼져 있음
```

## 파일 요약 쓰는 법

검수자는 보통 작성자 본인이다. 목표는 설명이 아니라 **틀렸을 때 무엇이 깨지는지**를 먼저 보여주는 것이다.

```
[역할 라벨]. [볼 곳]이 [틀린 상태]면 [결과].
```

1. **역할 라벨** — 파일의 일반 역할이 아니라 이 PR에서 맡은 일. 명사구 15자 안팎.
2. **틀리면-문장** — 긍정 조건으로. 부정("안 ~하면")은 한 번까지. 줄표는 쓰지 않는다.
3. **한 줄 = 확인 지점 하나.** 화면 한 줄(90자)을 넘기지 않는다. 넘치면 이유부터 버린다.
4. **줄 수 = 서로 다르게 깨지는 확인 지점의 수.** 최대 3줄. 해명으로 줄을 늘리지 않고,
   확인 지점이 여럿인 큰 파일을 한 줄로 욱여넣지도 않는다.
5. **트레이드오프는 `결정: [고른 것]. [치른 값].`** 으로 마지막 줄에. 이유가 아니라 치른 값을 쓴다.
6. **배너는 혼자 선다.** "위와 같이" 금지 — GitHub은 경로순이라 읽는 순서를 보장 못 한다.

### 확인 지점 고르는 순서

돌려보지 못한 곳 → 에러 없이 조용히 깨지는 곳 → 범위 밖으로 번지는 곳.

**코드에 이미 가드가 있으면 확인 지점이 아니다.** 후보에서 뺀다.
**틀리면-문장이 안 써지면 위험도를 `low`로 내리고 라벨만 쓴다.** 지어낸 위험보다 "안 돌려봤다"가 값지다.

### 위험도

틀렸을 때 **번지는 범위**로 가른다. 파일 크기나 변경량은 기준이 아니다.

| 값 | 기준 |
| --- | --- |
| `high` | 이 기능 밖으로 번지거나 측정·데이터 전체가 무효가 된다. PR당 3개까지 |
| `mid` | 이 파일이 맡은 부분만 틀린다 |
| `low` | 틀리면-문장을 지어내야만 쓸 수 있다. 라벨만 쓴다 |

`low`가 절반쯤 나와야 정상이다. 전부 경고면 아무것도 경고가 아니다.

### 쉬운 말로 쓴다

**판정: 이 PR을 만들지 않은 사람이 읽고 무슨 말인지 아는가.**

- 약어와 내부 용어를 쓰지 않는다. 괄호로 푸는 것도 차선이다 — 먼저 쉬운 말을 찾는다.
- 코드 식별자는 꼭 필요할 때만. 이름은 어차피 diff에 보인다.
- 상수 이름 대신 값과 뜻으로 (`TIMEOUT_MS` → "5초 안에 안 오면").

### 쓰지 않는 것

안심 문구("의도한 동작이다") · 구현 변명("~라서 ~로 미뤘다") · 막아둔 위험 나열 ·
위치 없는 추상어("핵심 로직") · 크기 언급("한 줄짜리다").

## 질문에 답하는 법

`status: "open"` 인 것만 처리한다.

| 종류 | 하는 일 |
| --- | --- |
| `question` | 답만 단다. 코드를 고치지 않는다 |
| `request` | 고칠 곳을 전수 확인해 정리한다. 고치는 주체가 따로 있다면 그쪽으로 넘기고, 넘겼다는 사실을 답에 적는다 |
| `memo` | 건드리지 않는다 |

- 카드 폭이 좁다. **세 문장 안쪽**으로 쓴다.
- 모르면 모른다고 쓰고, 무엇을 확인하면 되는지 적는다.
- 질문이 틀린 전제 위에 있으면 전제부터 바로잡는다.
- 사람이 되물으면 그 메모는 다시 `open`이 된다. 앞선 답을 덮어쓰지 말고 `reply`로 잇는다.

## 형식이 섞였을 때

```bash
node cli/notes.mjs move <owner/repo> <pr> <noteId> <새 경로>   # 파일을 잘못 찾아간 메모 옮기기
node cli/notes.mjs normalize <owner/repo> <pr>                 # 저장 형식을 현재 규칙으로 맞추기
```
